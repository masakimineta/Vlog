# 運用ガイド

このリポジトリを実際にどう使うかの手順書です。
特に「素材は外部ストレージ、記録はリポジトリ」という運用の具体的なやり方を説明します。

## 全体像

管理する場所は 2 つに分かれています。

| | 置く場所 | 中身 | 容量 |
|---|---------|------|------|
| **リポジトリ** | PC のローカル + GitHub | 企画書・台本・撮影計画・編集メモ・公開情報（テキストのみ） | 数 MB |
| **素材** | 外付け SSD + バックアップ | 撮影した動画・音声・書き出しファイル | 数十〜数百 GB |

この 2 つをつなぐのが **フォルダ名** です。

```
リポジトリ                          外付け SSD
episodes/EP001-京都の朝さんぽ/  ←→  Vlog素材/EP001-京都の朝さんぽ/
        ↑ 同じ名前にする ↑
```

同じ名前のフォルダが両側にあるので、リポジトリで `EP001` の編集メモを開けば、
SSD のどのフォルダを見ればいいかが名前だけで分かります。

さらに、`撮影計画.md` の「素材の保存先」に**どの SSD の・どのパスか**を書いておくことで、
SSD が複数台になっても・PC を買い替えても素材にたどり着けます。

### なぜ動画をリポジトリに入れないのか

- GitHub は 1 ファイル 100 MB を超えるとプッシュが拒否される（動画は簡単に超える）
- Git は差分管理が効かないバイナリを毎回まるごと保存するため、書き出しを重ねるだけで容量が倍々に増える
- Git LFS を使っても無料枠は 1 GB で、Vlog 1 本分にも足りない

## 最初に 1 回だけやる準備

### 1. リポジトリを PC に clone する

```bash
git clone https://github.com/masakimineta/Vlog.git
cd Vlog
```

### 2. 外付け SSD に名前を付ける

**これが一番重要です。** ドライブレター（Windows の `E:`）や `/Volumes/無題` のままだと、
挿す順番でパスが変わってしまい、後から「どの SSD だったか」が分からなくなります。

- macOS: Finder でディスクを右クリック →「名称変更」
- Windows: エクスプローラーでドライブを右クリック →「名前の変更」

`VLOG-01` のように、**ラベルシールを貼って本体にも同じ名前を書いておく**と確実です。

### 3. SSD に素材用の親フォルダを作る

```
VLOG-01/
└── Vlog素材/        ← ここにエピソードごとのフォルダが増えていく
```

### 補足: SSD を使わない場合

お試しで撮るときや短い動画なら、**PC 内蔵ドライブや Google ドライブでも構いません。**
この運用は「保存先を文字で書き残す」だけなので、保存先の種類は問いません。

```markdown
- **保存先**: MacBook 内蔵 `~/Movies/Vlog素材/EP001-テスト/`
- **バックアップ先**: Google ドライブ `Vlog/素材/EP001-テスト/`
```

ただし 2 点だけ気をつけてください。

- **2 か所に置くルールは変わりません。** PC 内蔵だけに置くと、PC が壊れた時点で素材も消えます
- **クラウド同期フォルダから直接編集する場合**、Google ドライブや iCloud の「ファイルオンデマンド／ストレージを最適化」がオンだと実体がクラウドにしかない状態になり、編集ソフトが読めない・極端に遅くなることがあります。編集中のフォルダはローカルに実体をダウンロードする設定にしてください

後から SSD に移したときは、`撮影計画.md` の保存先を書き換えるだけです。

```markdown
- **保存先**: 外付け SSD「VLOG-01」→ `Vlog素材/EP001-テスト/`（2026-05-10 に PC 内蔵から移動）
```

## エピソード 1 本の流れ

### ステップ 1: エピソードを作る（企画時）

リポジトリ側:

```bash
./scripts/new-episode.sh 001 京都の朝さんぽ
```

SSD 側に**同じ名前**のフォルダを作ります:

```
VLOG-01/Vlog素材/EP001-京都の朝さんぽ/
├── 01_映像/
├── 02_音声/
├── 03_写真/
├── 04_BGM効果音/
├── 05_プロジェクト/
└── 06_書き出し/
```

コマンドで作るなら（macOS の例）:

```bash
mkdir -p "/Volumes/VLOG-01/Vlog素材/EP001-京都の朝さんぽ"/{01_映像,02_音声,03_写真,04_BGM効果音,05_プロジェクト,06_書き出し}
```

そのうえで `企画書.md` → `台本.md` → `撮影計画.md` を書き、コミットします。

```bash
git add episodes/EP001-京都の朝さんぽ/
git commit -m "EP001 企画・台本・撮影計画を追加"
git push
```

### ステップ 2: 撮影する

`撮影計画.md` のカットリストを見ながら撮影し、**撮り終えたカットのチェックボックスを埋めます**。
スマホでも GitHub 上から見られるので、現場では画面で確認するだけでも構いません
（チェックは帰宅後にまとめて付けても OK）。

### ステップ 3: 素材を SSD にコピーしてリネーム（撮影当日）

SD カードから SSD の `01_映像/` にコピーし、[命名規則](命名規則.md) に沿ってリネームします。

```
20260412-EP001-A001-清水寺.mp4
20260412-EP001-B012-手元.mp4
```

**カット番号（A001、B012）は `撮影計画.md` のカットリストの番号と一致させます。**
これが揃っていると、編集時に「編集メモの A001 って、どのファイルだっけ」を探さずに済みます。

コピーが終わったら、**必ず 2 か所目にもコピー**します（クラウド or 2 台目の SSD）。
SD カードのフォーマットは、2 か所へのコピーが済んでから行います。

### ステップ 4: 保存先を `撮影計画.md` に記録する ← ここが運用の要

`episodes/EP001-京都の朝さんぽ/撮影計画.md` の一番下を、実際の値で埋めます。

```markdown
## 素材の保存先

- **保存先**: 外付け SSD「VLOG-01」 → `Vlog素材/EP001-京都の朝さんぽ/`
- **バックアップ先**: Google ドライブ `Vlog/素材/EP001-京都の朝さんぽ/`
- **総容量**: 68 GB
- **撮影後の確認**: [x] 全カットを再生して問題がないことを確認した
- **バックアップ確認**: [x] 2 か所にコピーし、コピー先でも再生できることを確認した
```

やることは**この 3 行を文字で書くだけ**です。何かを同期したりリンクを張ったりはしません。

書いたらコミットします。

```bash
git commit -am "EP001 撮影完了、素材の保存先を記録"
git push
```

#### 書き方のポイント

| 良い書き方 | 避ける書き方 | 理由 |
|-----------|------------|------|
| 外付け SSD「VLOG-01」 → `Vlog素材/EP001-.../` | `E:\Vlog素材\EP001-...` | ドライブレターは挿す順番で変わる |
| Google ドライブ `Vlog/素材/EP001-.../` | クラウドにあります | どのサービスのどこか分からない |
| 68 GB | （空欄） | 復元やコピーの時間・空き容量の見積もりに使う |

Mac のフルパス（`/Volumes/VLOG-01/...`）を併記しても構いませんが、
**ボリューム名だけは必ず含めてください**。それさえあれば、どの PC からでも特定できます。

### ステップ 5: 編集する

編集ソフトのプロジェクトは SSD の `05_プロジェクト/` に置き、
その場所を `編集メモ.md` の冒頭に記録します。

```markdown
- **編集ソフト**: DaVinci Resolve
- **プロジェクトファイルの場所**: SSD「VLOG-01」 → `Vlog素材/EP001-京都の朝さんぽ/05_プロジェクト/`
```

編集しながら `編集メモ.md` の「使うカット」「使わないカット」「BGM・効果音」を埋めていきます。
BGM の表を埋めておくと、公開直前にクレジット表記を調べ直さずに済みます。

書き出したファイルは `06_書き出し/` に置き、`編集メモ.md` の書き出し履歴に 1 行足します。

### ステップ 6: 公開する

`公開情報.md` を仕上げ、[公開チェックリスト](公開チェックリスト.md) を確認して公開します。
公開後、`公開情報.md` に URL と公開日を追記し、`episodes/README.md` の一覧を「公開済み」に更新します。

```bash
git commit -am "EP001 公開、URL を記録"
git push
```

## この運用が効いてくる場面

記録する手間の見返りは、あとから返ってきます。

**半年後に「あの映像をもう一度使いたい」となったとき**
GitHub で `episodes/` を開き、該当エピソードの `編集メモ.md` を見れば、
使ったカット番号と、SSD のどこにあるかが 1 分で分かります。

**SSD が 2 台目・3 台目になったとき**
「EP001〜EP008 は VLOG-01、EP009 からは VLOG-02」といった状態でも、
各エピソードの `撮影計画.md` にボリューム名が書いてあるので迷いません。

**PC を買い替えたとき**
`git clone` するだけで、企画・台本・編集メモ・公開情報がすべて戻ります。
素材は SSD にあるので、つなぎ直せば続きから作業できます。

**SSD が壊れたとき**
`撮影計画.md` のバックアップ先を見れば、どこから復元すればいいかが分かります。
容量も書いてあるので、ダウンロードにかかる時間の見当も付きます。

## コミットのタイミング

厳密でなくて構いませんが、この 4 回を目安にすると履歴が読みやすくなります。

| タイミング | コミットメッセージの例 |
|-----------|---------------------|
| 企画・台本・撮影計画を書き終えたとき | `EP001 企画・台本・撮影計画を追加` |
| 撮影が終わり保存先を記録したとき | `EP001 撮影完了、素材の保存先を記録` |
| 編集が終わったとき | `EP001 編集メモを更新、v3 で書き出し` |
| 公開したとき | `EP001 公開、URL を記録` |

## よくある詰まりどころ

**Q. SSD をつながずに編集メモだけ見たい**
リポジトリはテキストだけなので、SSD がなくても、スマホからでも GitHub 上で読めます。
撮影計画のカットリストを現場で確認する使い方が特に便利です。

**Q. 素材をうっかりリポジトリに入れてしまった**
`.gitignore` で主要な動画・音声の拡張子は除外済みなので、`git add` しても入りません。
もし別の拡張子で入ってしまい、まだコミット前なら `git restore --staged <ファイル>` で外せます。
コミット済み・プッシュ前なら `git reset --soft HEAD~1` でコミットを取り消してから外してください。

**Q. フォルダ名を後から変えたくなった**
両側（リポジトリと SSD）を同じ名前に変え、`撮影計画.md` の保存先も直します。
ただし公開後のエピソードは、混乱の元になるので変えないほうが無難です。

**Q. 1 本のエピソードで複数の SSD にまたがってしまった**
`撮影計画.md` の保存先を 2 行に分けて、どちらに何が入っているかを書いてください。

```markdown
- **保存先**:
  - 映像 A001-A012: SSD「VLOG-01」 → `Vlog素材/EP001-.../01_映像/`
  - 映像 B001-B030: SSD「VLOG-02」 → `Vlog素材/EP001-.../01_映像/`
```
